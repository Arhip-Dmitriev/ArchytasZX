ARCHYTASZX DOCUMENTATION
========================

The archytaszx Command and Shell

Applies to: ArchytasZX 2.0.x
Implementation: archytaszx.repl.shell


1. SYNOPSIS
-----------

    archytaszx [OPTIONS]                       interactive shell
    archytaszx [OPTIONS] FILE ...              run command files
    archytaszx [OPTIONS] -c CMD [-c ...]       run commands given on the command line


2. OPERANDS
-----------

Every positional operand is a file of engine commands. The files are run in the order given,
in one session, after every -c command. When neither a -c option nor a file is given, the
interactive shell starts.


3. OPTIONS
----------

3.1 General

  --help                 Print the usage summary and exit.
  -c CMD, --command CMD  Run CMD as one line. Repeatable; the lines run in order, before any
                         file.
  --unicode              Print Unicode text instead of ASCII.
  --no-concrete-axioms   Rewrite with bound dimensions kept symbolic: the axioms defined only
                         at a concrete dimension never match, and the other axioms match
                         without substituting bound values.

3.2 Views

The view decides how the diagrams engine commands print are shown. Exactly one may be given;
the default is --dirac.

  --dirac,     -dirac      Dirac notation.
  --zx,        -zx         ZX diagrams drawn with matplotlib (same as --zxrender).
  --zxrender,  -zxrender   ZX diagrams drawn with matplotlib; Unicode without an image
                           protocol.
  --zxunicode, -zxunicode  ZX diagrams on a Unicode character grid.
  --zxascii,   -zxascii    ZX diagrams on an ASCII character grid.
  --both,      -both       Dirac notation and the matplotlib ZX drawing.
  --raw,       -raw        Full ZX graph listings, nothing summarised or capped.

3.3 Saving images

  --images DIR        Also save every matplotlib ZX drawing in DIR, as NNNN-zx.EXT with
                      NNNN counting from 0001. EXT is set by the format setting (section 6):
                      png by default, pdf in publication mode.
  --images_white DIR  As --images, with black drawings on a white background.

PDF drawings embed their fonts; SVG drawings carry their text converted to paths.

3.4 Notation

  --publication       Label ZX drawings in the paper's notation with LaTeX fonts
                      (section 9.3). Sets the publication setting for this run.


4. EXIT STATUS
--------------

  0     Every line ran without error.
  1     At least one line reported an error, or standard output was closed.
  2     Usage error, or a file could not be read (nothing is run in that case).
  130   Interrupted by Ctrl-C outside a running command.

A line that fails reports its error and execution continues with the next line; the status is
determined at the end.


5. THE INTERACTIVE SHELL
------------------------

5.1 Prompt

The prompt is the name of the working directory followed by the number of the next line:

    Архитас(1):

A continuation line is prompted with dots in place of the name.

5.2 Input lines

Each input line is handled as follows, a leading colon being optional:

  - A blank line or a line starting with # does nothing and is not recorded.
  - history lists the lines entered in this session.
  - quit or exit leaves the shell (as does end of input).
  - A shell command (section 6) changes the shell's settings.
  - Any other line is an engine command (ENGINE_COMMANDS.txt).

A line ending in a backslash is joined to the next. A line that is only load, or @NAME =,
opens a block: the lines after it, up to a blank line, are the diagram source.

5.3 History

On a terminal, line editing and history are provided by readline. The history persists across
sessions in ~/.archytaszx_history, at most 1000 lines.

5.4 Errors

Errors are printed as lines beginning with "error:", in red when colour is enabled (standard
output is a terminal and NO_COLOR is not set). After a failed command, the detail command
shows the engine's full error record.


6. SHELL COMMANDS
-----------------

  Command                Effect
  ---------------------  ------------------------------------------------------------------
  dirac                  View Dirac notation.
  zx, zxrender           View ZX diagrams drawn with matplotlib.
  zxunicode              View ZX diagrams on a Unicode grid.
  zxascii                View ZX diagrams on an ASCII grid.
  both                   View Dirac notation and the matplotlib ZX drawing.
  raw                    View full ZX graph listings.
  listing                Toggle the graph listing printed under each ZX drawing.
  doubled                Toggle drawing a mixed diagram doubled, its conjugate sheet shaded
                         (Unicode and ASCII grids mark it with *).
  publication            Toggle the paper's notation in ZX drawings (section 9.3).
  config                 Show the image settings and the configuration file path.
  config KEY VALUE       Set an image setting: size (a number in (0, 10]), color ("auto",
                         #rgb, #rrggbb or a matplotlib colour), format ("auto", "png",
                         "pdf" or "svg") or publication ("true" or "false").
  config save            Write the settings to the configuration file.
  config reset           Restore the default settings.
  help [CMD]             List every command, or show one command's usage.


7. COMMAND FILES
----------------

A command file is UTF-8 text with one engine or shell command per line, a leading colon
optional. Files given together share one session: diagrams named by an earlier file are
visible to a later one. A relative FILE path in a command file (certificate lean FILE)
resolves against that file's directory.

An indented line continues the command above it on a new line, so a diagram spans several
lines under load or @NAME =. Blank and comment lines inside such a block are skipped. A line
ending in a backslash is joined to the next with a space. From
examples/deutsch_jozsa_proof.azx:

    @out_const =
        count n
        repeat n: X(0 -> 1)
        t = Z(0 -> 1) phase{k: -k/d}
        e = Z(1 -> 0) phase{k: k/d}
        scalar d^(-(n+1)/2)

    load
        count n
        repeat n: X(0 -> 1) -> F^4                          # data qudits
        X(0 -> 1) phase{k: -k/d} -> F^3 -> u = X(2 -> 1)    # target, through U_const
        inputs u.in1
        scalar d^(-n/2)

    decide against @out_const
    certificate lean deutsch_jozsa_constant.lean


8. TERMINAL IMAGES
------------------

Drawn diagrams are shown inline in terminals implementing the kitty graphics protocol, the
iTerm2 inline image protocol, or sixel; the protocol is detected from the environment, or
forced with ARCHYTASZX_IMAGES (INSTALL.txt, section 4.3). Where no protocol is available, or
standard output is not a terminal, drawings are replaced by Unicode text. Image size and
colour are set by the configuration file (INSTALL.txt, section 4.1).


9. ZX DRAWINGS
--------------

Implementation: archytaszx.repl.zxdraw (layout and drawing), archytaszx.repl.terminal (image
protocols, configuration)

9.1 Layout

A drawing reads left to right: the inputs (in 0, in 1, ...) form the first column and the
outputs the last. A wire from an output port to an input port runs rightwards; a node fed from
an input sits as far left as its wires allow, any other node as far right. Each connected
component keeps its own shape and is placed, in order (those holding inputs first), just below
the components already placed in the columns it occupies; a component without inputs or
outputs takes the first free space that fits it. Columns and rows that would be empty are
removed.

Every port leaves its node at its own point: a node with several legs on one side spreads them
over that side, one row per leg. In the grid views a node with more than one leg on a side
carries a heavy bracket, each leg leaving it on its own row.

Wires never share a segment, never pass behind a node and never end at a node they are not
attached to. Two wires that cross do so at right angles: the grid views draw the crossing as
┼ (+ in ASCII, where corners are . and '), the matplotlib view leaves a gap in the lower wire.
Two wires that would exchange the same two rows across a channel are moved a row apart, so they
cross once. Junctions occur only inside
nodes. A wire from a node to itself is drawn as a loop beside the node.

9.2 Nodes and labels

  Glyph (matplotlib)                        Grid     Node
  ----------------------------------------  -------  -----------------------------------
  light circle labelled Z                   Ⓩ        Z spider
  dark circle labelled X                    Ⓧ        X spider
  black triangle, input at the tip          ◀W       W node
  white triangle, input on the flat side    ▷T       triangle T
  grey triangle, labelled T^-1              ▶T⁻¹     inverse triangle
  yellow square labelled F                  [F]      Fourier box
  wedge labelled S, product leg left        ⊳S       splitter
  wedge labelled B, product leg right       ⊲B       binder

The ASCII view writes (Z ...), (X ...), <W, |>T, |>T^-1, [F], >S and <B. A spider's label stands
next to it; a long label is wrapped, or set smaller, beside its node.

The scalar is written to the left of the drawing, level with the middle of the first
component; a scalar of 1 is not written. Each wire is labelled with its dimension, at 85 % of
the label size, at the point where it leaves its first end.
When every wire has the same dimension the labels are omitted and the drawing states the
dimension once beneath it.

9.3 Phase notation

By default a spider's label repeats the diagram source, with phases in turns:

  Source                          Label
  ------------------------------  -----------------
  phase{1: alpha}                 α@1
  phase{1: theta, 2: phi}         θ@1, φ@2
  phase{k: k/d}                   k/d @k
  weight{1: lambda}               w: λ@1
  phase{1: p} weight{1: r}        p@1 · w: r@1

and the drawing states "phases in turns" beneath it. At a concrete dimension, phases that are
a fixed multiple of the index are written as one family, such as k/3 @k.

In publication mode (--publication, the publication command or the publication setting) the
labels follow the paper's definitions: the phase vector (α_1, ..., α_{d-1}) in radians, with
α_0 = 0. A turn value v is written 2πv and simplified, each phase symbol in it standing for an
angle in radians: phase{1: alpha} is labelled α, phase{1: alpha + 1/3} α + 2π/3 and
phase{k: k/d} (2πk/d)_k. A vector at a symbolic dimension whose only entry is at index 1 is
written as that entry alone; otherwise its entries are listed up to the last one set and the
unset remainder is written 0, ..., 0, as in (θ, φ, 0, ..., 0). A weighted spider is drawn as a
Z box (an X box for an X spider) labelled with its coefficient vector of entries w_k e^{iα_k},
for example (λ), (1, λ, 1, ..., 1) or (r e^{ip}), a multiple of π in an exponent written first,
as in e^{2πi/3}. Matplotlib text is set in Computer Modern with serif text. No phase unit is
stated.

9.4 Bang boxes

A bang box is drawn as a dashed rectangle (double lines in the grid views) with a ! tag in its
top-left corner and its multiplicity in its top-right corner, both inside the box. A leg in a
port box is kept one row clear of its node's other legs in the matplotlib view. A nested box
lies strictly inside its parent with space on every side. A box over ports wraps each leg where
it leaves its node. Where a wire crosses a box border the border is marked: a dot in the
matplotlib view, ╫ or ╪ in the Unicode view, * in the ASCII view.

9.5 Summaries

A diagram of more than 150 nodes that comes from a summed state is summarised: each summed term
is drawn as one box and each chain of splitters or binders as one node. The drawing then
states "summarised: one box per term".

9.6 Line weight

Matplotlib drawings place every line on whole points and draw it 1 pt wide, so wires and
outlines have one weight in PDF and SVG output at any zoom that is a multiple of 72 dpi.
