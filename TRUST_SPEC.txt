1. GOAL
-------

1.1 Today. Every exported Lean theorem is proved over the Net semantics
(archytaszx/lean/ArchytasZX/Net.lean). The networks are built by Python
(archytaszx/semantics/lean_net.py, `_Export.translate`): label allocation, bundled labels for
bang boxes (Kind.Bun towers, ZB/XB/WB tails, chains of multiplicities, Fam/bundL tables). A
bug there would make Lean prove a true statement about the wrong diagram. That translation is
the remaining trusted component.

1.2 Already done (2026-10-30), the model to follow. archytaszx/lean/ArchytasZX/Diagram.lean:
  - `Diagram` (nodes `DNode`, wires `Port × Port`, boundary `outs`/`ins`) is the engine's
    diagram as data; `Diagram.eval` is its meaning, defined directly (sum over a value on each
    wire of the product of the node tensors at the values on their legs), with no labels.
  - `Diagram.toNet off` builds the network; `Diagram.check` is a Bool well-formedness check;
    `DEqual_iff` proves `DEqual E s₁ D₁ s₂ D₂ ↔ Equal E s₁ (D₁.toNet o₁) s₂ (D₂.toNet o₂)`.
  - Python: `_Export.diagram_literal` and `_Export.diagram_theorem` in lean_net.py emit
    `D{i}`, `D{i}_net : D{i}.toNet off = N{i} := by decide +kernel`, and a final theorem
    `{name}_diagrams` stated with DEqual. Hooked into lean_net.finish, lean_sym (non-family)
    and lean_refute (non-family, negated). Only bang-box-free diagrams are covered.
  Read Diagram.lean and those Python functions first.

1.3 Target claim, to be made true and documented:

  Every theorem and refutation the engine exports to Lean, families included, has a final
  Lean statement over (A) the engine's diagrams as data, with a meaning defined directly in
  Lean, and (B) in a second stage, the text of the engine command file itself, parsed and
  given meaning inside Lean. No Python-computed object enters a final statement except
  literals that are checked against a Lean computation from (B)'s source text.

  The trust argument that must hold: Python may compute anything, but if it computes it
  wrongly, Lean rejects the file; it can never make Lean accept a statement whose meaning
  differs from the Lean definitions applied to the user's diagram.

Not goals: changing what the engine proves, changing search, the completeness rules, gaps
2-10 of LEAN_GAPS.txt.


2. STEP 1: SEMANTICS OF DIAGRAMS WITH BANG BOXES
------------------------------------------------

2.1 Read: archytaszx/diagram/bangbox.py (BangBox, node_scope, port_scope, parent, Mult,
    instantiate_symbol and what it does to boundary order and to wires leaving a node box),
    archytaszx/diagram/graph.py, lean_net.py `translate`, `node_chain`, `labelled`,
    `induction_lemma`, and the Lean files Bundle.lean (Fam, Fam.env, digsC, bundled, Bun),
    Port.lean (port boxes), FuseB.lean, Unfuse.lean. Write down in the progress file, with
    examples, exactly which box configurations `translate` accepts (everything else raises
    NetUnsupported and needs no coverage).

2.2 Extend `Diagram` in Diagram.lean with boxes: a box has a multiplicity (an index into the
    multiplicity values `ks`, as in Fam), an optional parent box, a node scope and a port scope,
    mirroring BangBox one to one. Box-free literals must stay valid (default the new field to
    []), so the existing bridge keeps working unchanged.

2.3 Define the meaning by expansion, in Lean: `Diagram.expand (ks : ℕ → ℕ) : Diagram` returns
    the box-free diagram with every box instantiated, and a family's meaning at `ks` is
    `(D.expand ks).eval`. This definition is the specification, so it must be short and
    readable, and it must agree with the engine's `instantiate_symbol`: same nodes, wires and
    boundary order, up to the renaming of node ids. Check that agreement by a script that, for
    every boxed diagram in examples/ and section 6's battery, at small multiplicities
    (0, 1, 2, 3 per symbol), compares the Lean `#eval` of `expand` against the Python
    instantiation; any mismatch is fixed on the Lean side (the engine's instantiation is the
    user-facing meaning) or recorded and decided in the progress file.

2.4 Family equality: `DEqualF` (name free) stating, for all multiplicity values, `DEqual` of
    the expansions at the base environment, where the dimension table holds only plain
    dimensions (no bundle indices). Expansion changes the boundary size with ks; DEqual
    already compares boundary dimension lists, so no extra arity condition is needed.


3. STEP 2: THE BRIDGE FOR FAMILIES
----------------------------------

3.1 Generalise `toNet` to boxed diagrams: produce exactly the bundled networks Python emits
    today (Bun towers, ZB/XB/WB tails, chains outermost first, Fam bundL table), so that
    `D.toNet … = N := by decide +kernel` closes against the existing exporter's nets. Where
    Python's output is not a function of the diagram alone (label offsets, H_OFFSET peel
    labels, bundle index allocation), give toNet the needed parameters, all checked by a Bool
    `check` as in Diagram.lean.

3.2 Prove, for every `ks`, under `check`:
      eval (F.env ks) (D.toNet …) σ = (D.expand ks).eval E₀ (unbundle σ)
    where `unbundle` splits each bundled boundary value into its digits in the engine's
    boundary order, and the corresponding InRange statements. Then prove the family version of
    DEqual_iff. Useful Mathlib facts: `finFunctionFinEquiv : (Fin n → Fin m) ≃ Fin (m ^ n)`
    with `finFunctionFinEquiv_symm_apply_val` (digit i of v is v / m ^ i % m, matching
    `digit`), `Finset.prod_univ_sum` / `Fintype.piFinset` (a product of sums is a sum over
    functions), `Finset.sum_bij`/`Equiv.sum_comp` for reindexing. Structure the proof by
    induction on the box nesting, one box at a time, reusing Bundle.lean's existing lemmas
    about Bun, copyOuts/copyIns and bundled wherever they apply.

3.3 Order: node boxes without crossing wires; node boxes with wires to outside nodes (fan-out);
    nested node boxes; port boxes; nested port boxes; boxes whose multiplicity is a compound
    expression. Each configuration that `translate` accepts must be covered or BLOCKED with
    its reason.

3.4 Exporters: extend `diagram_literal`/`diagram_theorem` to boxed diagrams and hook the family
    branches: lean_net (families and nested inductions), lean_sym (the `∀ … : ℕ, Equal
    (F.env …)` branch), lean_refute (the `¬ ∀` family statement). The final theorem of every
    export is the DEqual/DEqualF one; keep the Net theorems as intermediate lemmas.

3.5 Deferred dimension constraints and mixed dimensions (LEAN_GAPS items 7, 8; the `mainM` /
    `Equal.of_mapDim'` path, `self.alias`): the diagram statement must use the diagram's own
    dimensions, with the constraints as hypotheses. Cover it or BLOCK it with the reason.
