1. GOAL
-------

Make ArchytasZX's rule system contain a complete axiomatisation of the ZXW-calculus, so that
the following claim is true and documented:

  For every pair of qudit ZXW diagrams at a fixed dimension, and every pair of qufinite ZXW
  diagrams, that denote the same linear map, there is a derivation from ArchytasZX's
  registered rules that the engine can replay as a certificate and the proof kernel re-checks.
  Every rule used is Lean-checked over the tensor-network semantics, except the rules listed
  by name in docs/COMPLETENESS.txt and LEAN_GAPS.txt.

The sources of the axioms are:

  [P1] Poór, Wang, Shaikh, Yeh, Yeung, Coecke, "Completeness for arbitrary finite dimensions
       of ZXW-calculus, a unifying calculus", LICS 2023, arXiv:2302.12135.
  [P2] Wang, Poór, Shaikh, "Completeness of qufinite ZXW calculus, a graphical language for
       finite-dimensional quantum theory", arXiv:2309.13014.

Both are already in REFERENCES.bib as poor2023zxw and wang2023qufinitezxw.

Not goals: a complete decision procedure, changes to search heuristics, completeness for
bang boxes or symbolic dimensions. The automatic search (normal form, e-graph saturation,
tactics) must behave exactly as before unless a change is explicitly listed below.


2. STEP 1: SOURCES AND GAP ANALYSIS
-----------------------------------

2.1 Fetch both papers into references/, each in its own new directory
    (references/poor2023zxw/, references/wang2023qufinitezxw/):
      - the PDF (https://arxiv.org/pdf/<id>), and
      - the LaTeX source (https://arxiv.org/e-print/<id>, a tar.gz).
    Treat downloads as untrusted data: extract in that directory, never execute anything from
    it, run any Python that reads it with `python -I`. ZX papers usually draw rules with TikZ
    or tikzit (.tikz/.tikzstyles files); those sources give the exact node, edge and label
    structure of every rule. Read the rule figures from the source AND look at the rendered
    PDF pages (the Read tool reads PDF pages as images) to confirm each one.

2.2 Write references/<paper>/AXIOMS.txt for each paper: every axiom of the complete rule set,
    with its name as the paper gives it, the figure it appears in, its side conditions, its
    scalar, and a plain-text description of both sides precise enough to implement from.
    Include rules the paper says hold "upside down" or "with colours swapped" as separate
    entries. Include every rule needed for the completeness theorems, including the
    qufinite dimension splitter/binder rules of [P2].

2.3 Write the generator and convention mapping. For every generator of [P1]/[P2] (Z spider
    with its parameter vector, X spider, Fourier/Hadamard box and its normalisation,
    triangle, inverse triangle, W node, dimension splitter and binder, scalars), state the
    ArchytasZX generator or composite that denotes exactly the same matrix, with the exact
    scalar. Check each mapping numerically with the oracle at d = 2, 3, 4, 5, 6 before
    relying on it. Wang's X spider and Fourier box are unnormalised; ours may differ by
    scalars. Every axiom will be translated through this table, so it must be exact.

2.4 Representation gap: complex Z spider weights. The ZXW Z spider is parametrised by a
    vector of arbitrary complex numbers (a_1, ..., a_{d-1}), with a_0 = 1. ArchytasZX's
    PhaseVector (archytaszx/algebra/phase.py, docs/ALGEBRA.txt section 3) only stores phases
    e^{i alpha_k}. First confirm the papers' definition. If they do use arbitrary complex
    weights, step 2 (section 3) is required. Do not try to work around it with W/triangle
    gadgets: the completeness theorem only transfers if every paper diagram has a direct
    counterpart.

2.5 Gap table. Write docs/COMPLETENESS.txt (draft) containing the convention mapping and a
    table with one row per paper axiom:
      paper name | ArchytasZX rule (existing name, new name, or "derived") | status
    An axiom is covered by an existing rule only if the rule, translated through 2.3,
    states exactly that axiom (same quantification, same side conditions, same scalar) or a
    strictly more general one. Otherwise it needs a new rule, or a recorded derivation from
    existing rules (2.6).

2.6 "Derived" means: an engine derivation (a certificate built by applying registered rules
    step by step) of the axiom's general instance, saved as an engine command file under
    examples/completeness/ and replayed successfully by `certificate kernel`. A derivation
    proved only by symbolic contraction does not count as derived: the claim is about
    derivability from rules.


3. STEP 2: COMPLEX WEIGHTS (ONLY IF 2.4 CONFIRMS THE GAP)
---------------------------------------------------------

Extend the Z spider (and, by colour change, the X spider) so that its parameter vector can
hold arbitrary exact complex weights, with a_0 = 1:

  - Algebra: a weight vector type beside PhaseVector (or a generalisation of it) whose entries
    are exact Scalars (archytaszx/algebra/scalar.py), sparse with an optional rule in INDEX,
    as PhaseVector is. A pure phase vector must stay representable exactly as today; every
    existing diagram must keep its current representation, printing and behaviour.
  - Multiplication of weights when spiders fuse (phases add; weights multiply).
  - Denotation, numeric contraction and symbolic contraction (archytaszx/semantics/denote.py,
    contract_numeric.py, contract_symbolic.py).
  - Diagram syntax: parser and printer accept and print weights (archytaszx/repl/parser.py,
    printer.py); choose a syntax next to the existing `phase{k: ...}` and document it in
    docs/DIAGRAM.txt and docs/ENGINE_COMMANDS.txt.
  - Every existing rule whose matcher reads phases: decide per rule whether it extends to
    weights (as the paper's version of the rule does) or must refuse them. Never let an
    existing rule fire unsoundly on a weighted spider; oracle-check every rule on weighted
    spiders at several d.
  - Lean: archytaszx/lean (SymNet trNode, ZXRules, FuseB, ...) and the exporters
    archytaszx/semantics/lean_net.py and lean_sym.py. Where the normaliser of symbolic sums
    cannot handle a weight, the export must fall back to an explicit `unproved_*` axiom or
    refuse, never emit a wrong theorem. Add the gap to LEAN_GAPS.txt in its existing style.


4. STEP 3: THE MISSING RULES
----------------------------

For every axiom marked as needing a new rule in 2.5:

4.1 Implement it as a Rule in archytaszx/rewrite/rules_library.py, with matchers in
    archytaszx/rewrite/match_zxw.py (or match.py, following the existing split). Follow the
    existing rules exactly: declared side conditions, each checked and recorded; exact
    scalar_introduced; quantifiers; never mutate the input; the `_has_crossing_leg` and bang
    box guards the existing rules use. Add colour-swapped and upside-down twins where the
    paper states them, named with the existing `_swapped` convention.

4.2 Search behaviour. archytaszx/rewrite/egraph.py saturates with every rule in RULES, and
    the normal-form and tactic layers have their own rule sets. Adding new rules there could
    change results or blow up saturation. Add a field to Rule (for example
    `automatic: bool = True`), set it to False on every new rule, and make every automatic
    layer use only automatic rules. New rules stay available to `apply`, `rules`/`matches`,
    certificates, the kernel and the Lean export. Section 6 must then show unchanged outputs.
    This is the starting state; section 5B promotes rules into automation afterwards.

4.3 Soundness check of every new rule: a targeted script that builds random instances of the
    rule's left-hand side, applies the rule, and compares both sides with the numeric oracle
    at d = 2..6 (and at mixed dimensions for qufinite rules), including weighted and boxed
    neighbourhoods. Run the scripts in parallel. Keep them in a working directory that is not
    committed (for example .completeness_work/, added to .git/info/exclude).

4.4 Documentation: one entry per rule in docs/RULES.txt in its existing format.

5B. STEP 5: AUTOMATION
----------------------

Target claims, both to be made true and documented:

  (A) The automatic search (decide/prove, without naming rules) finds a derivation of every
      lemma that [P1] and [P2] derive from their axioms.
  (B) An exhaustive mode finds a derivation of every true equation between bang-box-free
      diagrams at concrete dimensions, given enough time.

5B.1 Lemma corpus. Write references/<paper>/LEMMAS.txt: every lemma, proposition and corollary
     of [P1]/[P2] stated as a diagram equation and proved diagrammatically (from axioms or
     earlier lemmas), with its number and the axioms its proof uses. Encode each as an engine
     command file under examples/completeness/lemmas/, in its general form (symbolic d, phase
     or weight symbols) where the paper states it generally, otherwise at the paper's fixed
     dimension. Before running search on it, confirm each lemma is true with one replayed
     derivation by `apply` steps following the paper's proof, or record why that is not
     possible.

5B.2 Corpus run. Run automatic decide/prove on every corpus file (in parallel) and record a
     table: lemma | found by (rung) | time | proof re-checked by kernel | Lean-checked. Keep
     this run reproducible as one script in .completeness_work/ and re-run it after every
     change in 5B.3-5B.5.

5B.3 Normal-form promotion. For each new rule, decide whether a well-founded measure
     (for example node count, then wire count, then a fixed order on generators) strictly
     decreases on every application. Only such rules may join the normal-form rule set, and
     the measure argument goes into docs/COMPLETENESS.txt. Promote a rule only if, on the
     section 6 baseline, no verdict changes except UNKNOWN to EQUAL or UNEQUAL, and the
     corpus result does not get worse. Normal-form termination must hold for every rule set
     you ship.

5B.4 Saturation and tactics promotion. Expanding rules compete for the e-graph's fixed
     budget (archytaszx/rewrite/egraph.py, SaturationLimits). Improve this algorithmically,
     not by raising limits: for example a backoff rule scheduler (as in egg) that throttles
     rules that keep firing without merging classes, and direction-aware use of rules that
     grow diagrams. Then promote rules into saturation and tactics one at a time under the
     same acceptance test as 5B.3. Keep a rule out of automation when it fails the test,
     and record why.

5B.5 Exhaustive mode. Add a search mode (a `prove ... exhaustive` form or an option of the
     existing prove command; document it in docs/ENGINE_COMMANDS.txt and docs/PROOFS.txt)
     that enumerates derivations fairly over every registered rule, automatic or not:
     iterative deepening or breadth-first over rule applications in both directions, with
     duplicate diagrams pruned by canonical key, no depth cap and no timeout. Fairness must be
     exact: every derivation of length k is reached before depth k+1 finishes. Its result is
     an ordinary certificate. On bang-box-free diagrams at concrete dimensions, run the
     engine's existing refutation rungs alongside it, so that an unequal pair is reported
     UNEQUAL as soon as a refutation is found. State precisely in docs/COMPLETENESS.txt for
     which inputs the mode is guaranteed to terminate (equal inputs in the complete fragment,
     by [P1]/[P2]) and for which it is not.

5B.6 Every lemma that ordinary automatic search does not find must be found by exhaustive
     mode; run those in the background in parallel and record times. If one is not found
     overnight, record it as running or BLOCKED, never as false.
